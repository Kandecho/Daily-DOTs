# 日报制作与协作流程

## 1. 稿件阶段核实

- 确定日期、时区和截稿点，优先公开的一手资料与可靠报道。
- 核实关键事实、数字、时间、因果关系和证据范围；不把目标、宣布、预测写成已经发生。
- 保留公开来源链接，将数据截点、样本范围与不确定性放进对应正文。
- 数量服从质量，允许少于五条主新闻或没有探索位。
- 元数据只保存排版所需信息；私人讨论、编辑聊天、任务标识、账号、本机路径和内部过程记录不入公开原稿。

本阶段完成事实与文字编辑。生成程序不重新事实核查；生成后不再安排重复的模型审稿。发现实质内容错误时，回到原稿做针对性修订并重新生成。

## 2. 生成与自动检查

```sh
python tools/daily.py editions/YYYY-MM-DD/原稿_YYYY-MM-DD.md --date YYYY-MM-DD
```

自动检查原稿结构、正文回读、来源 URL、导航、字体缺字和单文件资源，最后才写正式 HTML。失败时先解决问题，不发布 `_build/` 中间页面。

默认不覆盖不同内容的成品；确认同一期修订后才加 `--overwrite`。修订说明可写在 Git 提交说明，不塞进阅读目录。

## 3. 一次轻量排版检查

打开刚生成的 HTML，确认：

- 目录日期、条数、标题正确，链接进入对应新闻。
- 正文无明显缺字、截断、横向溢出，地图与图注对应。
- 横向翻页、页内纵向滚动可用；回目录始终可达、不遮正文。
- 来源链接保留，明暗主题无明显对比度问题。

这里检查渲染与交互，不重复全面新闻审查。程序测试不冒充真实手机触控验收；未做或受限时如实记录在本地。

## 4. 更新网站入口

排版验收通过后，在项目根目录运行：

```sh
python tools/site.py
```

脚本只更新根目录 `index.html`；最新一期按实际期次日期选择，往期自动倒序排列，链接全部使用相对路径，适配 GitHub Pages 的仓库子路径与本地打开。已有日报原稿、HTML、交互和内嵌字体不变。没有“今日”自动改日期，也不每日手工设计首页。

`editions/YYYY-MM-DD/` 只放验收后的完整一期：`原稿_YYYY-MM-DD.md` 与 `全球晚间新闻_YYYY-MM-DD_翻页.html`。已有旧期 `翻页试读.html` 兼容保留，不同时留下两个候选成品。缺文件、原稿元数据日期不一致、HTML 标题日期不一致或重复候选会使入口更新失败，原首页不被覆盖。未完成稿件放在本地工作区，避免混入待发布目录。

## 5. 提交前检查

每期主要文件只有原稿和 HTML；生成代码、测试、公开排版约定和流程文档可以一起维护。

```sh
git status --short
git diff --check
git diff --cached --stat
git diff --cached --name-only
```

逐项核对，不用 `git add -f` 绕过忽略规则：

- 只有本次需要的期次和工程变更，公开原稿与成品一致。
- 没有私人说明、账号、密钥、令牌、聊天记录、非公开来源或机器专属路径。
- 没有 `_build/`、备份、日志、缓存和完整字体。
- 字体许可和地图出处保留。

工程代码或模板变更后运行完整测试。日常内容变化至少完成生成自检和轻量排版检查。提交作者身份由维护者实际配置，不冒用他人姓名和邮箱。

## 6. GitHub Pages 上传与验证

目标仓库为 [Kandecho/Daily-DOTs](https://github.com/Kandecho/Daily-DOTs)。首次接入时，在仓库 **Settings → Pages** 选择 **Deploy from a branch → main → / (root)**。根目录 `.nojekyll` 让静态文件直接发布，不增加 Actions 工作流。仓库所有者负责建立仓库与授权，维护者在授权范围内上传并维护网站。

每次发布按以下顺序执行，不把本地生成、提交成功与网站更新混为一谈：

1. 本地保留原稿和 HTML，完成生成自检、轻量排版验收、首页更新与提交前检查。
2. 将本期两个文件和 `index.html`，以及确实修改的公开工程文件，提交到已授权仓库的 `main`。
3. 核对远程分支已到达预期提交，确认 Pages 对应部署完成。
4. 访问网站固定入口，检查显示的实际期次、阅读链接、往期链接和原稿链接；新闻内的目录与翻页阅读方式保持不变。
5. 发布失败时保留本地两个文件，排查授权范围内的问题；未验证线上成功前不声称网站已更新。

本站仅为静态阅读入口，无后端、数据库或登录。发布范围不包括 `_build/`、本地备份、内部过程记录和完整字体。原创部分的许可由仓库所有者另行决定，不因公开上传自动添加 MIT 等许可。

Git 不含完整字体与本地备份，不是完整运行环境备份。迁移需安装 Python/fontTools 并准备指定字体；已有单文件 HTML 则可直接离线阅读。
