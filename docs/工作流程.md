# 工作流程

贡献范围、分支与提交说明见 [贡献指南](../CONTRIBUTING.md)；原稿格式和版式见 [排版约定](排版约定.md)。

刊名只在 `tools/core.py` 定义：报头 `NAME`，副题 `SUBTITLE`。原稿 `title` 必须等于 `SUBTITLE`。

## 发布一期

1. 把原稿放到 `editions/YYYY-MM-DD/原稿_YYYY-MM-DD.md`，目录日期、文件名日期和 `issue_date` 必须一致。没写完的稿子不要放进 `editions/`。
2. 用 `python tools/daily.py editions/YYYY-MM-DD/原稿_YYYY-MM-DD.md` 生成本期本地留档，再用 `python tools/site.py --build` 统一构建检查 `_site/`。缺字体先跑 `python tools/fetch_fonts.py`；失败就修原稿或环境，不绕过检查、不发布中间文件。
3. 打开 `_site/index.html` 和本期 HTML 看一遍（手机宽度，约 390px）：
   - 目录页的日期、条数、标题对；点进去是对应的那条；
   - 没有缺字、截断、横向溢出；地图标签不重叠，和图注对得上；
   - 左右翻页、页内上下滚动、「回到目录」「首页」都能用；
   - 明暗两种主题都看得清。
   程序检查不等于真机检查；没看成就如实说没看。
4. 提交并推送本期原稿。Actions 会重建全部期次和首页并发布 Pages；本地 HTML 留着，不入 Git。

修订已经发布的一期：先改原稿，再加 `--overwrite` 重新生成。修订说明写在提交信息里，不写进页面。`--overwrite` 不能覆盖另一个日期的成品。

## 改程序、模板或文档

- 改了版式或交互：更新测试，跑 `python -m unittest discover -s tests`，再用浏览器看一期真实日报。
- 改了生成结果：用 Python 3.12 跑 `python tools/site.py --build` 重建全部期次检查。合并后由 Actions 构建发布。
- 测试用的虚构数据要标 `TEST`，不能当新闻发布。

## 提交前检查

```sh
git status --short
git diff --check
git diff --cached --stat
```

对照 [贡献范围](../CONTRIBUTING.md#贡献范围) 确认暂存区只含这次需要的文件；涉及原稿改动时，本地 HTML 已按当前原稿生成。

## 推送之后

推送成功不等于网站已经更新。确认 Actions 的构建和 Pages 部署都成功，再打开 <https://kandecho.github.io/Daily-DOTs/> 看最新一期。构建或检查失败时不发布，线上保留上一版；不能只凭推送成功就说「已发布」。
